Research Focus

This benchmark comprehensively evaluates INT8 quantization of Large Language Models (LLMs) across different GPU architectures (RTX4080, RTX4070). The study measures performance, quality retention, and memory efficiency to guide practical deployment decisions.

Key Research Questions:

  • How much speedup can INT8 quantization achieve?
  • What is the quality trade-off compared to full precision?
  • How do different GPUs impact performance?
  • Which model/GPU combination is best for specific use cases?

Dataset Integrity

All data has been verified and validated:

  • Source Models: GPT-2, Qwen1.5-1.8B, LLaMA-2-7B (officially released)
  • Quantization: INT8 format using standard quantization tools
  • Hardware: Dedicated RTX4080 and RTX4070 systems with identical configurations
  • Testing: Each configuration tested 10 times with consistent results
  • Datasets: Standard benchmarks (HuggingFace datasets for evaluation)
  • Evaluation Framework: ROUGE, BLEU, and throughput metrics

  • LLaMA-2-7B (7B params): Large, powerful, for complex tasks

Key Concepts ExplainedKonsep Utama Dijelaskan

What is INT8 Quantization?

Definition: INT8 (8-bit integer) quantization converts model weights and activations from full precision (FP32 or FP16) to 8-bit integers, reducing memory and computation.

How it Works:

  • Original (FP32): Each weight uses 32 bits, storing decimal numbers like 0.37461293...
  • INT8: Each weight uses only 8 bits, storing integers from -128 to 127
  • Conversion: Maps the full range of FP32 values to 8-bit integer range with scaling factors

Why It Works Despite Fewer Bits:

  • Neural networks are robust: They can tolerate some precision loss
  • Quantization-aware training: Models can be fine-tuned to work well with INT8
  • Statistical properties: INT8 distributes representation across the dynamic range
  • Redundancy in parameters: Many weights carry minimal information

Benefits of INT8:

Aspect FP32 INT8 Improvement
Bits per weight 32 bits 8 bits 4x smaller
Memory for 7B model 28 GB 7 GB 4x reduction
Computation speed 1x baseline 3-4x faster 3-4x speedup
Quality loss 100% ~90% ~10% loss

Evaluation Metrics Explained

1. BLEU Score (Bilingual Evaluation Understudy)

  • What it measures: How many words/phrases in the model output match the reference (human) output
  • Range: 0 to 1 (higher is better)
  • How it works: Compares n-grams (1-word, 2-word, 3-word, 4-word sequences)
  • Example: If human says "the cat sat on the mat" and model says "the cat is on the mat", BLEU gives partial credit for matching "the cat", "on the mat", etc.
  • Best for: Translation tasks

2. ROUGE Scores (Recall-Oriented Understudy for Gisting Evaluation)

  • ROUGE-1 (Unigram): Measures overlap of individual words (1-grams)
  • ROUGE-L (Longest Common Subsequence): Measures the longest sequence of words that appear in both outputs in the same order
  • Range: 0 to 1 (higher is better)
  • Better for: Summarization and generation tasks (more lenient than BLEU)
  • Example ROUGE-1: Compares "the cat sat" vs "the dog sat" - gives credit for "the" and "sat" matching
  • Example ROUGE-L: Finds the longest matching sequence between outputs

3. Throughput (Tokens per Second)

  • What it measures: How many words (tokens) the model can generate per second
  • Why it matters: Determines practical speed of the model in real use
  • Example: 127 tokens/sec means the model generates 127 words per second
  • For users: 50 token response takes ~0.4 seconds (responsive)

4. Memory Usage (VRAM)

  • What it measures: How much GPU memory (VRAM) the model uses
  • Why it matters: Determines if you can run the model on your GPU
  • Example: RTX4070 has 12 GB VRAM - if model needs 8 GB, you can fit it
  • Quantization benefit: INT8 reduces VRAM by 75% compared to FP32

Apa itu Kuantisasi INT8?

Definisi: Kuantisasi INT8 (bilangan bulat 8-bit) mengkonversi bobot dan aktivasi model dari presisi penuh (FP32 atau FP16) ke bilangan bulat 8-bit, mengurangi memori dan komputasi.

Cara Kerjanya:

  • Original (FP32): Setiap bobot menggunakan 32 bit, menyimpan angka desimal seperti 0.37461293...
  • INT8: Setiap bobot menggunakan hanya 8 bit, menyimpan bilangan bulat dari -128 hingga 127
  • Konversi: Memetakan jangkauan penuh nilai FP32 ke jangkauan bilangan bulat 8-bit dengan faktor penskalaan

Mengapa Ini Berhasil Meskipun Bitnya Lebih Sedikit:

  • Jaringan saraf kuat: Mereka dapat bertoleransi terhadap beberapa kehilangan presisi
  • Pelatihan yang sadar kuantisasi: Model dapat disesuaikan untuk bekerja baik dengan INT8
  • Sifat statistik: INT8 mendistribusikan representasi di seluruh jangkauan dinamis
  • Redundansi dalam parameter: Banyak bobot membawa informasi minimal

Manfaat INT8:

Aspek FP32 INT8 Peningkatan
Bit per bobot 32 bit 8 bit 4x lebih kecil
Memori untuk model 7B 28 GB 7 GB Pengurangan 4x
Kecepatan komputasi 1x baseline 3-4x lebih cepat Percepatan 3-4x
Kehilangan kualitas 100% ~90% ~10% kerugian

Metrik Evaluasi Dijelaskan

1. Skor BLEU (Bilingual Evaluation Understudy)

  • Apa yang diukur: Berapa banyak kata/frasa dalam output model yang cocok dengan output referensi (manusia)
  • Jangkauan: 0 hingga 1 (lebih tinggi lebih baik)
  • Cara kerjanya: Membandingkan n-gram (urutan 1-kata, 2-kata, 3-kata, 4-kata)
  • Contoh: Jika manusia mengatakan "kucing itu duduk di atas tikar" dan model mengatakan "kucing itu ada di atas tikar", BLEU memberikan kredit sebagian untuk pencocokan "kucing itu", "di atas tikar", dll.
  • Terbaik untuk: Tugas terjemahan

2. Skor ROUGE (Recall-Oriented Understudy for Gisting Evaluation)

  • ROUGE-1 (Unigram): Mengukur tumpang tindih kata-kata individual (1-gram)
  • ROUGE-L (Subsequence Common Terpanjang): Mengukur urutan kata terpanjang yang muncul di kedua output dalam urutan yang sama
  • Jangkauan: 0 hingga 1 (lebih tinggi lebih baik)
  • Lebih baik untuk: Tugas peringkasan dan pembuatan (lebih toleran daripada BLEU)
  • Contoh ROUGE-1: Membandingkan "kucing duduk" vs "anjing duduk" - memberikan kredit untuk "duduk" yang cocok
  • Contoh ROUGE-L: Menemukan urutan kecocokan terpanjang antara output

3. Throughput (Token per Detik)

  • Apa yang diukur: Berapa banyak kata (token) yang dapat dihasilkan model per detik
  • Mengapa penting: Menentukan kecepatan praktis model dalam penggunaan nyata
  • Contoh: 127 token/detik berarti model menghasilkan 127 kata per detik
  • Untuk pengguna: Respons 50 token membutuhkan waktu ~0.4 detik (responsif)

4. Penggunaan Memori (VRAM)

  • Apa yang diukur: Berapa banyak memori GPU (VRAM) yang digunakan model
  • Mengapa penting: Menentukan apakah Anda dapat menjalankan model di GPU Anda
  • Contoh: RTX4070 memiliki 12 GB VRAM - jika model membutuhkan 8 GB, Anda dapat memuatnya
  • Manfaat kuantisasi: INT8 mengurangi VRAM sebesar 75% dibandingkan dengan FP32

Load Quantized ModelMuat Model Terkuantisasi

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "gpt2"  # or "Qwen/Qwen1.5-1.8B", "meta-llama/Llama-2-7b"

# Load with INT8 quantization
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    load_in_8bit=True,
    device_map="auto"
)

tokenizer = AutoTokenizer.from_pretrained(model_name)

Run InferenceJalankan Inferensi

prompt = "Once upon a time"
inputs = tokenizer(prompt, return_tensors="pt")

with torch.no_grad():
    outputs = model.generate(
        **inputs,
        max_length=100,
        temperature=0.7,
        top_p=0.95
    )

response = tokenizer.decode(outputs[0], skip_special_tokens=True)
print(response)

FastAPI ServerServer FastAPI

from fastapi import FastAPI
from transformers import AutoModelForCausalLM, AutoTokenizer

app = FastAPI()
model = AutoModelForCausalLM.from_pretrained("gpt2", load_in_8bit=True)
tokenizer = AutoTokenizer.from_pretrained("gpt2")

@app.post("/generate")
async def generate(prompt: str, max_length: int = 100):
    inputs = tokenizer(prompt, return_tensors="pt")
    outputs = model.generate(**inputs, max_length=max_length)
    return {"response": tokenizer.decode(outputs[0])}

Scoring MethodologyMetodologi Penilaian

Composite Score Formula

Score = (0.25 × Throughput) + (0.20 × ROUGE-1) + (0.15 × BLEU) + (0.15 × ROUGE-L) + (0.15 × VRAM) + (0.10 × Residency)

Weight Justification:

  • Throughput (25%): Most important - faster inference benefits all users
  • ROUGE-1 (20%): Measures semantic understanding - critical for quality
  • BLEU (15%): Evaluates n-gram precision - important for accuracy
  • ROUGE-L (15%): Captures long-range dependencies - for coherence
  • VRAM (15%): Efficiency metric - matters for resource-constrained settings
  • Residency (10%): Stability metric - low residency = better performance consistency

Formula Skor Komposit

Skor = (0.25 × Throughput) + (0.20 × ROUGE-1) + (0.15 × BLEU) + (0.15 × ROUGE-L) + (0.15 × VRAM) + (0.10 × Residency)

Justifikasi Bobot:

  • Throughput (25%): Paling penting - inferensi lebih cepat menguntungkan semua pengguna
  • ROUGE-1 (20%): Mengukur pemahaman semantik - penting untuk kualitas
  • BLEU (15%): Mengevaluasi presisi n-gram - penting untuk akurasi
  • ROUGE-L (15%): Menangkap dependensi jarak jauh - untuk koherensi
  • VRAM (15%): Metrik efisiensi - penting untuk pengaturan terbatas sumber daya
  • Residency (10%): Metrik stabilitas - residency rendah = konsistensi performa lebih baik
